# v1.6.4

## 中文

### 性能
- 在节点列表中将鼠标停留在节点名上（或键盘聚焦）150ms，会预先加载该节点 24 小时的延迟数据，点击进入后图表通常立即显示。
- 已加载的延迟数据在当前页面内缓存 5 分钟：切回看过的时间范围或节点时立即显示，并在后台刷新；不写入本地存储。
- 首次打开详情页时，延迟等数据请求直接根据网址发出，不再等待节点列表返回。
- 加载中保留图表区域高度，页面不再跳动。

### 修复
- 实时数据、节点列表、离线记录到达引起的重绘不再重建延迟图，悬停读数不会被打断。

### 验证
- `npm run check`
- `npm run package`

## English

### Performance
- Resting the pointer on a node name in the list (or focusing it) for 150ms prefetches its 24h latency, so the chart usually appears as soon as the page opens.
- Loaded latency data is kept in memory for 5 minutes: returning to a range or node shows it at once and refreshes it in the background. Nothing is written to storage.
- On a first visit the detail page requests its data straight from the URL instead of waiting for the node list.
- The chart area keeps its height while loading, so the page does not jump.

### Fixes
- Redraws caused by live data, the node list or outage records no longer rebuild the latency chart, so a hover readout is not interrupted.

### Verification
- `npm run check`
- `npm run package`
